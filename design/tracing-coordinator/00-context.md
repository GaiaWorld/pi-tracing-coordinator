## 素材与内部参考

- **接入提示词已全文阅读。** 它要求：业务通信两侧登记 Trace 关联；发送协调决定时保留同一个 Trace 标识和原绝对过期时间；接收端使用实际来源进程交给本地记录器处理。关联、选择、去重传播、历史导出由 pi_logger 管理。
- **../pi_db_server 是服务端参考。** 已读公共入口、服务构建主路径、类型注册入口和 Trace 附件处理。可参考服务注册、统一编解码和终端装配；数据库事务、实例管理和表整理不构成本库需求。
- **../pi_db_terminal 是客户端参考。** 用户已确认它就是所称的 pi_db_client。已读公共入口、构建前段、RPC 发送路径、Trace 附件编码和销毁清理。可参考发送、超时、终端及宿主运行时的配套关系；其全部发现、重连和版本配置能力是否需要，尚未确定。
- **../pi_logger 是直接接入依据。** 已读公共重导出、协调身份与通知契约、初始化主路径、记录器接入方法及部分相关测试。TraceNotifier 在独立通知线程上被串行调用，应快速提交发送任务；提交后的异步失败由通信库观测。尚未完成全部相关实现链和验收证据核验。
- **兼容性事实。** 两个数据库参考库使用 OpenTelemetry 0.30 和外置 tracing-opentelemetry；当前 pi_logger 使用 OpenTelemetry 0.33 和内置桥接。参考代码的导入与类型不能直接照搬，L5 需核对实际版本和兼容边界。
- **2026-10-14 事实校准。** 上一条为 L0 原时点快照；本轮回读 pi_db_server=0.5.15、pi_db_terminal=0.5.13，均已声明 OpenTelemetry 0.33 和 tracing-opentelemetry 0.34。本库仍复用 pi_logger 导出类型与内置桥接，旧快照不能当当前依赖事实。
