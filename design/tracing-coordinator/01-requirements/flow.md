<a id="registration-flow"></a>
## 关联登记职责（旧流程已撤回）

关联跟踪、登记、缓存和通知目标选择全部由宿主完成。本库不提供本地或远程登记入口，不调用record_peer，也不保存Trace—Peer关联。原两端登记流程因职责误解撤回；保留此锚点供历史链接定位，不能将旧日志或旧归档中的登记能力作为当前需求。纠正来源见[变更日志](../index/changes.md)与[当前状态](../../../docs/DEVELOPMENT_CONTEXT.md#ctx-current)。

## 唯一上报通知流程

图定位：selection-flow；范围为一次宿主指定通知的业务步骤，2026-10-16差量确认版；不是源码派生调用链。

~~~mermaid
flowchart LR
    H["宿主给定目标、上报决定、本跳来源"]
    V["发送前置检查与准入"]
    C["按既定精度转换并由宿主codec编码"]
    S["至多一次send提交"]
    R["返回本地结果"]
    D["接收框架前置解码"]
    X["框架拒绝；不进入业务函数"]
    P["本库业务参数校验"]
    B["本库接收准入"]
    A["一次apply_remote_selection"]
    E["尝试一次本地拒绝日志"]
    O["仅本地事件发布成功"]

    H --> V
    V -->|"通过"| C
    V -->|"失败；零提交"| R
    C -->|"成功"| S
    C -->|"失败；零提交"| R
    S --> R
    S -. "可能送达；与发送返回无完成先后保证" .-> D
    D -->|"失败"| X
    D -->|"成功交付业务参数"| P
    P -->|"非法"| E
    P -->|"合法"| B
    B -->|"关闭、无记录器或中毒等拒绝"| E
    B -->|"获准"| A
~~~

| 节点 | 责任及出口 | 冻结需求来源 |
|---|---|---|
| H | 宿主给定目标、决定和本跳来源；关联信息由宿主管理。 | 指定发送、关联归宿主、直接来源 |
| V、C | 本库依既定次序检查、准入、转换，使用宿主预绑定codec编码；失败返回、零提交。精确调用顺序由L7合同规定。 | 一次提交尝试、传输保真、失败可观察 |
| S、R | 本库至多调用一次既有提交出口；结果仅表示本地提交情况，不自动重试。 | 一次提交尝试、提交与完成分开 |
| S→D | 宿主通信及框架推进；可能未送达，不补齐送达保证。提交错误也不能据此断言外部必然零效果。 | 提交与完成分开、职责边界 |
| D、X | 框架解码失败不进入本库业务函数或记录器；本库不承诺该阶段日志。 | 失败观测责任、非法输入无副作用 |
| P | 本库校验业务参数；非法则尝试一次拒绝日志，不进入binding或记录器。 | 非法输入、失败可观察 |
| B | 合法参数才请求接收准入；关闭、记录器不可用或中毒等拒绝，返回后尝试一次日志，零记录器调用。 | 不可用拒绝、关闭保护 |
| A、E | 获准后锁外调用记录器一次；未发布只按真实结果尝试一次拒绝日志，不猜原因或重试。 | 接收交接、失败可观察 |
| O | 仅表示本地事件发布；后续选择、去重、传播和导出由记录器独立推进。 | 提交与处理完成分开、职责边界 |

### 读图说明

入口是宿主给定通知。发送前置失败零提交，进入提交步骤至多一次；发送返回与远端处理没有完成先后保证。图中的V/C是业务步骤概览，不替代L7的精确调用顺序。实线表示本地步骤推进，虚线表示可能送达；未送达就没有接收分支。

接收端先经过框架解码：失败在X结束，不进入业务函数；成功才进入P。业务参数非法、接收准入拒绝和事件未发布分别在本库业务入口后处理，尝试一次日志。日志是否实际记录受宿主过滤和日志接收者控制。

只有合法且获准的输入才调用记录器一次。O不表示后续处理完成；图中没有发送方应答或远端确认。

### 生命周期与限制

关闭停止新准入，关闭前已准入的调用允许收尾，不撤回已提交消息。绑定状态锁只保护准入及状态转换，编解码、记录器调用、日志和资源析构均在锁外。

宿主终端、运行时和记录器守卫仍由宿主管理。Fory类型表由宿主冷路径完成集中登记、发布及预绑定；本库不再拥有旧的进程级私有准备缓存。关闭不清除client/宏params的codec持有或宿主线程局部缓存。当前行为尚未实现或验收。
