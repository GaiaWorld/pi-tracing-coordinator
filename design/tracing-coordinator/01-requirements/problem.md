# tracing-coordinator · 问题与范围（L1）

**状态：修正后定稿/冻结，2026-10-15。** 用户确认本轮需求正文、流程图及源表，并同意进入 L5 定向修正。本库仅有上报通知，关联登记、缓存和目标选择归宿主；旧两端登记方案撤回，历史留日志。冻结不等于实现或功能验收。

<a id="problem"></a>
## 问题

同一条业务处理链可能经过多个进程。发生异常或超时时，单个进程保存的历史不足以解释整条链。宿主已经负责跟踪、登记并缓存同一 Trace 涉及的参与进程，需要通过本库向指定进程传递上报决定，使接收进程能够处理自己保存的历史。

Trace 是同一次业务处理链的既有追踪标识。通知提交成功不表示消息已经送达，也不表示接收进程有历史数据或已经完成上报。

<a id="scope"></a>
## 本次范围

- 同一个库提供发送和接收能力，各参与进程同时可发可收。
- 支持同机和跨主机通信，参与进程直接通信。
- 宿主决定发送时机、目标和内容，本库执行指定操作。
- 有且只有一种需要发送和接收的协调消息：上报通知；接收后交给既有记录器处理。
- 每次指定通知只尝试一次提交，成功或失败都不自动重试；返回本地提交结果。
- 提供本库自身功能的初始化、绑定和关闭，复用宿主已有通信环境。
- 验证本库自身输入、资源、错误、并发和生命周期边界。
- 面向 Windows x64、Linux x64，构建和测试以 WSL 为基准。

<a id="out-of-scope"></a>
## 不在范围内

| 事项 | 责任边界 |
|---|---|
| 决定何时发送、寻找相邻进程、选择通知目标 | 宿主及其记录器负责。 |
| 独立中转服务或另一套通信环境 | 复用宿主已有环境。 |
| 附件编解码、发送/接收处理、观察器和 Span 上下文绑定 | 全部由宿主实现。 |
| 身份认证、通知授权、自建身份或启动代际协议 | 本库使用宿主提供的身份及路由。 |
| 关联跟踪、登记、缓存、查询及目标选择 | 全部归宿主；本库不提供本地或远程登记能力，也不维护关联表。 |
| Trace 选择、传播去重、历史采集与导出 | 宿主及其 pi_logger 负责，本库只接入通知传输。 |
| 自动重试、回滚、远端处理确认 | 每次提交尽力一次，不增加反馈协议。 |
| 持久化、恢复、重放、补单、上报后持久化管理 | 本库信息限定为当前运行期的内存信息。 |
| 校时、补偿时钟偏差、续期 | 部署方与记录器按各自职责处理。 |
| 修改依赖库或保证其全部内部资源有硬上限 | 不越过库间与逻辑间的明确边界。 |
| 关闭宿主共享通信环境或记录器守卫 | 宿主负责其生命周期。 |
