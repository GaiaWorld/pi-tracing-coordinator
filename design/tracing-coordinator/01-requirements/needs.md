## 需求与验收标准

| 需求 | 可测验收标准 | 来源 |
|---|---|---|
| 发送决定属于宿主 | 未收到指定调用时不生成通知；收到调用后只提交给定目标和内容。 | 用户确认。 |
| 各参与进程可发可收 | A、B 均可向对方提交上报通知并通过接收接入处理，不依赖独立中转。 | 部署确认及 2026-10-15 单消息纠正。 |
| 支持同机和跨主机 | 两种部署均验证上报通知，部署方式不改变业务内容。 | 平台与通信范围确认。 |
| 关联与目标归宿主 | 未有上报通知调用时，本库不登记、缓存或查询关联，也不选择目标；接到调用后只访问指定目标。 | 用户 2026-10-15 明确纠正。 |
| 一次调用一次提交尝试 | 每次通知调用至多提交一次；校验、准入或编码失败时不提交，提交失败直接报告，不自行重试或转存。 | 单向通知与失败语义；用户单消息确认及本轮收束。 |
| 每次上报传输保真 | Trace 保持不变；期限统一为 100 纳秒精度，发送前只舍弃不足 100 纳秒的部分，最多提前 99 纳秒、绝不延后。其后的通知传输和接收交接保持同一规范化期限。记录器随后按自身契约裁剪期限。 | 用户 2026-10-14 明确统一 100 纳秒精度；[精度规则](notes.md#deadline-precision)。 |
| 来源表示直接发送进程 | A→B→C 时 B 接收来源 A、C 接收来源 B；身份由发送宿主提供，本库传递，不把最初发起者或目标当作来源。 | 来源责任确认。 |
| 提交与处理完成分开 | 本地成功不声称送达、远端接受或导出完成；发送不等待远端应答。 | 单向通知约束。 |
| 本库边界内失败可观察 | 发送侧校验、编码及提交错误返回；通知实现的同步失败记录。接收侧收到框架交付的业务参数后，参数非法、记录器不可用、绑定关闭和事件未发布由本库记录。框架交付业务参数之前的解码拒绝不承诺由本库记录；异步通信错误沿宿主实际上下文观测，不强制逐 Trace 或逐操作关联。 | 2026-10-16用户接受按职责划分；[明确边界与依据](notes.md#typed-static-boundary)。 |
| 记录器不可用不阻止通信启动 | 本库接收功能拒绝处理并记录，不能把通信启动报告成记录器已可处理。 | 启动确认。 |
| 过期由记录器处理 | 已过期决定不产生新的上报传播；本库不续期、不补偿时钟偏差。 | 素材与期限确认。 |
| 重启不继承旧内存 | 重启后不恢复旧关联与选择；固定或变化的通信身份都合法，随后通知按当前记录器处理。 | 纯内存与身份确认。 |
| 关闭保护本库与共享宿主 | 关闭后不接纳新协调操作；已接纳调用按约定收尾，不撤回已提交消息；宿主其他通信业务继续可用。 | 关闭边界与本次门禁。 |
| 非法服务输入无错误副作用 | 服务解码失败或业务参数非法时拒绝，不进入上报处理；保持安全解码要求。底层报文处理由宿主通信负责。 | 安全目标及用户服务层职责澄清。 |
| 本库不新增无界积压 | 不建立额外通知缓存或后台队列；提交拒收直接保留，不能转存后伪报成功；临时资源随调用释放。 | 责任边界确认。 |
| 不越过职责边界 | 不修改依赖库状态表示、传播规则、持久化或共享生命周期；保证均限定本库出口。 | 用户硬约束。 |
